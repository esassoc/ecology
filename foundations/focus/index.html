Focus

The focus indicator is the keyboard user's cursor. It is the one visual state you never get to remove — and the only one this system paints in two colours, because one is not enough to guarantee it can be seen.

The ring is two bands

Tab through anything on this site. The ring you see is a brand band with a near-black halo outside it. Both are 2px.

…and me

The split exists because a single brand-coloured ring cannot be relied on to conform. Measured on 2026-08-16, the default ring managed 2.95:1 against the raised surface, 2.88:1 against the canvas and 2.66:1 against the sunken surface — all short of the 3:1 that SC 1.4.11 requires. That is not a bad colour choice to be corrected: whatever a spoke picks for its brand is picked for brand reasons and can land anywhere on the luminance scale. So identity and contrast were split onto separate bands, and only the second one carries the conformance obligation.

This is the accessibility literature's universal focus indicator — pair a light and a dark outline so one of them always contrasts — with the brand kept as the inner band rather than discarded.

The five tokens

TokenMaps toWhat it is
--focus-ring-color --color-border-default-focus The brand band, inner. Carries identity, not contrast.
--focus-ring-halo --color-border-default-focus-halo The contrast band, outer. This is the one that has to clear 3:1.
--focus-ring-width --border-width-focus Thickness of each band. 2px.
--focus-ring-offset 2px literal Sizes the innermost halo band. 0 gives a plain two-band ring.
--focus-ring-halo-spread derived The box-shadow spread that puts the halo one band beyond the outline. Never hand-write this.

A spoke re-points --color-background-brand and the inner band follows, because --color-border-default-focus chains off the brand semantic rather than the ramp. The halo deliberately does not follow: a spoke must not be able to break the ring's conformance by changing its brand and not noticing.

One surface genuinely inverts this — esa-button variant="chrome" sits on a dark app bar and takes its ring from currentColor. A component on a dark ground re-points --focus-ring-halo to a light value locally. That is what a tier-3 hook is for.

Writing a focus rule

The house shape, and the only one you should need:

.thing:focus-visible {
  outline: var(--focus-ring-width) solid var(--focus-ring-color);
  outline-offset: var(--focus-ring-offset);
  box-shadow: 0 0 0 var(--focus-ring-halo-spread) var(--focus-ring-halo);
}
  • outline for the brand band, never box-shadow. Forced-colors modes replace backgrounds, borders and box-shadows with system colours; outlines survive. Fourteen components painted their ring with box-shadow alone until 2026-08-16 — every form control we ship — which meant the entire form layer had no keyboard indicator in Windows High Contrast Mode. outline has followed border-radius in every engine since 2021, so the rounded ring that motivated box-shadow is no longer a reason.
  • :focus-visible, not :focus — the ring appears for keyboard and programmatic focus but not on a mouse click. Two exceptions, both deliberate: text entry uses :focus-within on the field wrapper (a ring on click is native behaviour for something you are about to type into), and esa-error-summary uses bare :focus because a user sent there by a failed submit did not click anything and :focus-visible heuristics can decline to paint.
  • Never a bare outline: none. If the ring belongs somewhere else — a chromeless input inside a bordered row — put a :focus-within ring on the row and say so in a comment. The reset on its own is a check-a11y block.
  • Inset the ring only when the box is clipped. outline-offset: calc(var(--focus-ring-offset) * -1) plus an inset halo, for a full-bleed row inside an overflow: hidden panel. A flush 2px inner ring has the same area as a 2px perimeter, so it still meets Focus Appearance — but an outward ring is easier to see and should be the default.

What each criterion asks, and how we meet it

Success criterionLevelAsks forHow we meet it
2.4.7 Focus Visible AA A visible indicator exists for anything that takes keyboard focus. Every focusable element paints the ring. check-a11y blocks removal at write time — including the unconditional `.thing { outline: none }` shape that the guard missed until 2026-08-16.
1.4.11 Non-Text Contrast AA The indicator contrasts 3:1 with adjacent colours. The halo band is outermost, so it is what sits against the page: 15.9:1 raised, 15.5:1 canvas, 14.3:1 sunken.
2.4.13 Focus Appearance AAA Contrasting area at least as large as a 2px perimeter of the element. Two 2px bands outside the box — double the minimum. The three inset rings are flush 2px, which matches the perimeter exactly.
2.4.11 / 2.4.12 Focus Not Obscured AA / AAA The focused element is not hidden behind other content. focus.css sets scroll-margin-block-start from --focus-scroll-margin. Any layout with sticky chrome must set it; the docs shell sets 76px for its 56px bar.

axe does not evaluate focus indicators at all. npm run a11y stayed green through every failure on this page, including three components that had deleted their ring outright. The test is a keyboard and your eyes.

Light DOM vs shadow DOM

A stylesheet cannot cross a shadow boundary, so the ring is delivered twice from one source of truth.

  • Light DOM — @esa/tokens/focus.css, imported by the spoke template's BaseLayout. It rings every a, button, summary, input, select, textarea, [tabindex] at zero specificity (:where()), so a component rule always wins. It also carries the :focus:not(:focus-visible) undo, which is what suppresses the browser's own ring only where ours replaces it.
  • Shadow DOM — each Lit component paints its own from the same five tokens (custom properties inherit through the boundary). The shared @esa/tokens/a11y.css is bridged in via a11y.ts and carries the forced-colors fallback, so a component listing a11y in static styles keeps a ring even where its own colours are overridden.

Until 2026-08-16 the only correct page-level focus rule in the repo lived in the docs shell — a file spokes never receive. Every light-DOM component we ship had a tokenised ring here and the browser default everywhere else.
