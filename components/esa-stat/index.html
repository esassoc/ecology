Stat

A single-metric block: a big display value, a readable label, and an optional muted caption. Replaces the bespoke .stat / .stat__value / .stat__label cluster every prototype re-implements.

Stable .astro import EsaStat from '@esa/ecology/esa-stat.astro';

Preview

With a caption

The sub line is muted meta — a delta, a reporting period, a qualifier. Keep it short enough not to compete with the label.

Accent

accent tints the value with --color-content-brand-secondary. Use it to single out one figure in a row — a headline number among supporting ones. A row where every stat is accented reads as no emphasis at all.

Stat rows

The component is a bare flex column with a transparent background and no padding of its own — the surface is the caller's job. Lay a row out with a layout primitive or a grid; wrap it in an esa-card when the group needs chrome. Deliberately no <esa-stat-group>: spacing between stats belongs to the page, not to the metric.

API

PropTypeDefaultDescription
value string | number required The metric itself — rendered large, in the display face.
label string required What the value counts. Sentence case, readable body size — not an uppercase overline.
sub string — Optional muted caption under the label (a delta, a period, a qualifier).
accent boolean false Tints the value with the brand secondary emphasis. Off by default keeps it primary text.

Accessibility

  • Renders plain <div>s — no heading semantics. The value is not an <h*>, so a stat row never disturbs the page's heading outline.
  • The value comes before the label in the DOM, which is also the reading order screen readers announce. Keep the label self-describing ("Active permits", not "Active") so the pair makes sense read aloud.
  • Abbreviate carefully: 1.2M is announced as written. Prefer the full figure, or add an aria-label at the call site.
  • accent is decoration, not meaning — never let the tint be the only signal that a number is the alarming one. Say so in the label or sub.

Theming surface

Every public token this component reads, extracted from its source at build time, split by blast radius: the hooks that belong to this component, then the shared and system tokens it consumes alongside everything else. The Resolves to column walks each token's real lineage — component → semantic → primitive → raw value — so you can see exactly where re-pointing it lands. A spoke re-skins by overriding these in its theme-<slug>.css; component internals are never edited. No hook for what you need? File it with /request-lego.
